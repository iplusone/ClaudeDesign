# AI時代の構造化デザイン実践ガイド

Claude Design を使いこなすための中核は、デザインを `デザインシステム` `テンプレート` `コピー` の3要素に分解して考えることです。

## 1. イントロダクション

Claude Design を使うとき、多くのユーザーは `Vibe Designing` に陥ります。

たとえば、次のような曖昧な依頼です。

```text
AIエージェンシーのランディングページを作って
```

この進め方では、生成結果に対して場当たり的な修正を繰り返すことになり、次の問題が起こります。

- トークンの浪費
- 一貫性の欠如
- 修正ループの長期化

特に、レイアウトの再生成はテキスト修正より重く、デザイン専用枠をすぐに消費します。

### 発想の転換

一流のAIクリエイティブ運用では、デザインを以下の3要素に分解します。

- `デザインシステム`: ブランドスタイル
- `テンプレート`: 骨組み
- `コピー`: 内容

この3要素を先に決めることで、AIの推測余地を減らし、初回の完成度を高めます。

## 2. 第1の柱: デザインシステム

デザインシステムはブランドの `ブループリント` です。これがないと、AIは毎回スタイルを変えてしまいます。

### 手順

1. 右側サイドパネルの `Design Systems` を開く
2. `Create New` をクリックする
3. 構造化したブランド定義を入力する

### 入力例

```text
[Brand Description]
革新的で信頼感のあるAI開発スタジオ。モダンでミニマルな美学を重視。

[Visual Identity]
- Colors: メイン #001F3F、アクセント #0074D9、背景 #FFFFFF
- Typography: 見出しは太字のサンセリフ体、本文は可読性の高いInter系
- Spacing & Rules: 8pxグリッド、ボタン角丸4px、シャドウは最小限
```

### 効果

- スタイルの一貫性が高まる
- AIの推測コストが下がる
- 初回出力がブランドに寄りやすくなる

視覚ルールが固まったら、次はレイアウトの骨格を固定します。

## 3. 第2の柱: テンプレート

テンプレートは、デザインシステムを着せる前の `スケルトン` です。

### 構築プロセス

1. Dribbble、Framer、`Examples` から理想レイアウトを探す
2. スクリーンショットをアップロードする
3. ブランド適用済みテンプレートとして再現させる
4. `Duplicate as Template` で保存する

### 推奨指示

```text
このレイアウトをブランドのビジュアルに合わせてテンプレートとして再現して。コピーはプレースホルダーで良い。
```

### 効果

- レイアウト試行錯誤を減らせる
- トークン消費を抑えられる
- 構造を再利用できる

形が整ったら、次は中身となる言葉をデザイン工程から切り離して準備します。

## 4. 第3の柱: コピー・スキル

Claude Design はデザインツールであり、コピー最適化の場ではありません。

### 基本方針

コピーは Claude Desktop や Claude Code の `Skill` で事前に作成します。

### Skillの役割

- ブランドボイスを踏まえる
- 過去の成功事例を参照する
- どのテンプレートセクションを使うか判断する
- セクションごとのコピーを出す
- Step 4 用の最終デザインプロンプトを作る

### 目指す出力

単なる文章ではなく、以下を含む命令書を生成させます。

- どのテンプレートを使うか
- どのセクションに何を入れるか
- ブランドとして守るべきこと

こうしておくと、デザイン時のAIは `何を書くか` ではなく `どう配置するか` に集中できます。

## 5. 実践: 統合ワークフロー

3つの柱が揃ったら、以下の順番で実行します。

- [ ] Step 1: デザインシステムを接続する
- [ ] Step 2: `From Template` で保存済みテンプレートを呼び出す
- [ ] Step 3: Skillが生成した詳細プロンプトを貼る
- [ ] Step 4: Claude Design に生成させる

AIから質問が返ってきたら、必要に応じて次のように返せます。

```text
decide for me
```

### 完成度の差

- `Cold One-shot`: 30%から50%
- `Structured Workflow`: 70%から90%

## 6. ブラッシュアップと実装

AIが80%を作り、人間が20%を仕上げます。最終品質を左右するのは `Taste` です。

### 4つの編集ツール

- `Direct edit`: テキストを直接修正する
- `Comments`: 特定要素に自然言語で変更を指示する
- `Draw`: レイアウト意図をスケッチで伝える
- `Tweaks`: カラーやバリエーションを切り替える

### 実装へのハンドオフ

`Share` から Claude Code へハンドオフできます。発行されたコマンドを使えば、静的なデザインを本物のアプリケーション実装へつなげられます。

### 注意点

- 研究プレビューのため、テキスト重なりやレンダリング不具合が起こる場合がある
- デザイン専用の週間枠は限られている
- Step 1 から Step 3 を飛ばして Step 4 に進むのは非効率

## 7. 結論

この手法の本質は、AIに任せる前に構造を人間が決めることです。

- 制作時間を大幅に短縮できる
- 品質の再現性が上がる
- 人間は判断に集中できる

一度作ったデザインシステム、テンプレート、Skill は継続的に使える資産になります。
