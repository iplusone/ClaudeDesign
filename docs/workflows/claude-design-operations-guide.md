# Claude Design 運用プロセスガイド

AIデザインワークフローを標準化し、短時間で一貫した高品質な成果物を出すための運用ガイドです。

## 1. はじめに

Claude Design によって、従来は数週間かかっていた高精度なデザイン制作を、数分から10分程度で進められるようになりました。

Claude Design は単なるウェブサイトビルダーではなく、以下のような複数モードを持つ制作エンジンです。

- `Prototype`: ワイヤーフレームや高精度UIの構築
- `Slide deck`: プレゼン資料の自動生成
- `From template`: 既存の成功パターンから開始
- `Other`: LinkedInカルーセル、インフォグラフィック、提案資料などの制作

このスピードを組織的な競争力に変えるには、場当たり的なプロンプト入力ではなく、再現可能な標準プロセスが必要です。

## 2. ボトルネック

`Vibe Designing` の問題は、AIに意思決定を任せすぎることにあります。

たとえば「AIエージェンシーのランディングページを作って」のような抽象的な依頼では、Claude は以下を毎回推測しなければなりません。

- 配色
- フォント
- レイアウト
- コピー

この推測の多さは、次の問題を引き起こします。

- トークンの浪費
- レイアウトの崩れ
- 一貫性の欠如
- 修正ループの増大

### 基本原則

運用の核心は、AIの役割を `意思決定者` ではなく `実行者` に寄せることです。

Claude Design を開く前に、以下を事前定義します。

- 色
- レイアウト
- 文章

これにより推測を減らし、初回出力の精度を高められます。

## 3. ステップ1: デザインシステムの構築

デザインシステムは、Claude に対するブランドの設計図です。これがないと、成果物は汎用的なAIテンプレートに見えやすくなります。

### ルール

すべてのプロジェクトで、プロンプト入力前に `Design Systems` からブランド定義を接続します。

### 必須項目

- [ ] Core mission
- [ ] Visual principles
- [ ] Primary / Secondary colors
- [ ] Typography
- [ ] Component styles

### 詳細チェック

- `Core mission`: ブランドの使命と存在意義
- `Visual principles`: モダン、信頼感、ミニマルなどの視覚原則
- `Primary / Secondary colors`: HEXコードで指定
- `Typography`: 雰囲気と優先フォント
- `Component styles`: ボタン形状、余白、カード、入力欄などのルール

Claude が提案したスタイルは、リファインメント機能で自社基準に合うまで調整します。

## 4. ステップ2: テンプレート化

デザインシステムが外装なら、テンプレートは骨格です。構造を先に固定することで、Claude にゼロからレイアウトを考えさせる必要がなくなります。

### 実践ステップ

1. `Examples` や外部サイトから優れたレイアウトを収集する
2. スクリーンショットを読み込ませ、ブランド適用した形で再構成させる
3. 特定案件のコピーを外した汎用構造にする
4. `Duplicate as Template` で保存する

### 推奨指示

以下のように伝えると、複数のパターンを一元管理しやすくなります。

```text
これらを自社のブランドで再現し、すべてのレイアウトを一つの場所にまとめたスライドデッキ形式で構築してください。
```

## 5. ステップ3: コピー作成スキルの定義

Claude Design はデザインツールであり、コピー試行錯誤の場ではありません。デザイン画面で文章を何度も詰めると、高価なデザイントークンを消費します。

### 方針

コピーは Claude Desktop や Claude Code の `Skill` で事前生成します。

### スキルでやること

- ブランドボイスを学習させる
- テンプレート構造を踏まえた文章を作る
- 使うセクションを判断する
- セクションごとの確定コピーを出す
- 最終的な統合プロンプトを作る

### 統合プロンプトに含める内容

- 使用テンプレート
- セクションごとのコピー
- ブランド指示

## 6. ステップ4: Claude Designでのビルド

ここは準備したアセットを統合し、最小回数で高品質な出力を得るフェーズです。

### 標準ビルドシーケンス

1. `From Template` からテンプレートを選ぶ
2. `Design Systems` からブランド定義を接続する
3. 統合プロンプトを貼り付ける
4. 必要なら次のように伝える

```text
Answer any clarifying questions or say "decide for me".
```

### 微調整ツールの使い分け

- `Direct edit`: 文言の直接修正
- `Comments`: 特定要素への変更指示
- `Draw`: レイアウト変更をスケッチで指示
- `Tweaks`: 色変更、モード切替、バリエーション確認

## 7. 開発連携

完成したデザインは、`Handoff to Claude Code` により実装フェーズへ渡せます。

### 連携フロー

1. デザイン画面からハンドオフ用コマンドをコピーする
2. Claude Code に貼り付ける
3. 実装要件を追加する

### 実装対象の例

- データベース
- ユーザーアカウント
- 決済機能
- フォーム送信
- フルスタックな画面実装

この連携により、PoC を短期間で動く製品に近づけられます。

## 8. 運用上の留意事項

### トークン管理

Claude Design の利用枠は、通常の Claude とは別の週次予算として考えます。準備なしの試行錯誤を繰り返すのは非効率です。

### 80/20の法則

この運用では、制作の80%をAIが担い、残り20%を人間の判断が担います。

#### AIが担うもの

- 構造の展開
- コードやUIの下書き
- レイアウト生成

#### 人間が担うもの

- ブランド哲学との整合性判断
- 情緒的な訴求の見極め
- 最終品質の判断

AIによって制作のボトルネックは小さくなります。そのぶん、価値の中心は `作る力` から `見極める力` に移ります。

## 9. 運用ルール要約

- デザイン前に `色` `レイアウト` `文章` を必ず定義する
- デザインシステムの接続を必須化する
- テンプレートを再利用前提で蓄積する
- コピー作成は Claude Design の外で済ませる
- Claude Design ではビルドと微調整に集中する
- 最後の品質判断は必ず人間が行う
